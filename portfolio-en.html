AI + automation | corporate education

Contracts and receipts read by LLMs, no typing

Problem

Contracts arrived as signed PDFs and receipts as photos or spreadsheets. The team typed everything by hand into monday.com, with errors and rework.

What I built

  • Pipeline that downloads the contract PDF, extracts the text and asks GPT-4o for the fields in a fixed format.
  • Validation before writing: client tax ID and installment total. Only empty fields are filled; divergences become a comment on the item; amendments only comment.
  • Receipt reading with a vision model and classification from a closed list of valid labels.

How it works

  1. PDF attached
  2. Extract text
  3. LLM (fixed JSON)
  4. Validate tax ID and installments
  5. Fill empty fields only
  6. Comment divergences

Results

  • Tested end to end with real contracts and 66 automated checks.
  • 16 n8n workflows in production for the same client (contracts, receipts, budget, notifications, scheduling).

Engineering safeguards

  • Idempotency key per entry: reprocessing a file never duplicates anything.
  • Error check after every write, because monday answers success even when a write fails.
  • Labels restricted to the exact list in the column, since a non-existent label is rejected silently.
  • Calls to monday go through an internal proxy: the token appears in no workflow file.

Stack: n8n, GPT-4o, monday.com GraphQL, Node.js

Travel logistics: from supplier email to itinerary PDF

Flight, hotel and transfer bookings arrived by email as PDFs and calendar files. The team read each voucher, typed it into monday and built the teacher's itinerary by hand.

What I built

How it works

  1. Daily schedule

  3. Read emails
  4. Create and link bookings
  5. Generate PDF
  6. Human review
  7. Send

Automation + WhatsApp | real estate developer

Lead distribution over WhatsApp without getting the number banned

Problem

Leads reached the CRM and had to reach the right broker fast. A burst of simultaneous sends had already caused a temporary block of the WhatsApp number.

What I built

How it works

  1. Lead assigned
  2. Build message
  3. Global queue
  4. WhatsApp
  5. Read webhook
  6. Weekly Excel

Engineering safeguards

  • Diagnosis by comparing executions, not by guessing.
  • Silent failures fixed: a native automation switched off with no error (leads idle for over 24 h, resent) and emails failing because of an OAuth credential (moved to SMTP on the client's own domain).

Prompts and LLM experiments

Three real prompts from my work, rewritten with generic data. The pattern is the same in all three: fixed output format, an explicit rule for what the model does not know, and validation in code before writing.

Extracting fields from a contract PDF

Fixed output format, no invented values, so code can validate before writing.

You extract data from service contracts.
Reply ONLY with JSON in the format below, no extra text.
Rules:
- If a field is not in the document, use null. Never infer or invent.
- Dates as YYYY-MM-DD. Amounts as numbers, no currency symbol.
- If the document is an amendment or another type, return "type": "amendment" and leave the other fields null.
Fields: type, client, tax_id, start_date, end_date, total_value, installments, installment_value, due_day.

Classification with a closed label list

The label must exist in the destination column; any other is silently rejected. The exact list goes in the prompt.

Classify the expense below into ONE label from the list, copying the text exactly as written (accents included).
List: Airfare | Lodging | Transfer | Class Hour | Venue Rental | Other
If none clearly applies, answer "Other".
Reply with the label only.

Vision: handwritten sheet with per-field confidence

The model admits when it could not read. An uncertain field becomes an alert for a human instead of wrong data.

Read the photo of the measurement sheet and return JSON following the provided schema.
For each field return { "value": ..., "confidence": "high" | "medium" | "low" }.
- If the text is illegible or ambiguous, value null and confidence "low". Do not guess.
- Measurements in centimeters, numbers with a decimal point.
- Do not fill blank fields with typical values.

Principles I apply

  • Fail loudly: if the right value cannot be written, the flow stops with a clear error.
  • Idempotency: reprocessing never duplicates. Every creation has a stable key.
  • Human in the loop when in doubt: the system sets the uncertain case aside instead of guessing.
  • Diagnose with evidence: execution history and comparison before touching code.
  • Secrets out of the code: tokens in credentials and proxies, never in an exported file.
  • Test business rules first: pure calculation, with stubs and reconciliation against the source.
